# MemBench v0.1 — Phased Implementation Plan

**Goal:** a runnable benchmark answering one question — *which model writes memory that actually helps later?* One command runs the full loop: every model observes the same session transcript → one fork per observation set (+ 3 controls) → every fork performs the same task under **two executors** → tokens, cost, success, search burden, and drift land in `results.jsonl` → scoreboard. Fully offline-testable with mocks; live runs are local-machine only. First live deliverable: a cost-estimate table for the OpenRouter credit sponsor, with real measured `usage.cost` numbers for both executor routes.

**Benchmark definition** (normative; `README.md` in this repo is the narrative version):

- **Variants per corpus item:** one per observer model, plus controls `none` (floor), `oracle` (hand-written ceiling), `shuffled` (another session's notes).
- **Executors (both first-class in v0.1):** `claude-cli` (Claude Code CLI — the production claude-mem consumer) and `openrouter-agent` (a minimal coding agent on `@openrouter/agent` — any OpenRouter model can execute). Scoreboard comparisons are **within one executor only**; cross-executor numbers appear only in the cost table.
- **Runs:** k≥3 per (item × variant × executor); report mean ± spread.
- **Headline metrics:** success rate (vs floor) and tokens-to-done (successful runs, vs floor + oracle). Supporting: % of oracle savings `(floor − model)/(floor − oracle)`, real cost (obs + exec sides), search burden (mem-search calls per run), drift rate (out-of-scope work, judge-flagged vs `task.md`). Observation count and XML parse notes are diagnostics, never headlined.
- **Cost formula** (for estimates): `N_models × (obs pass) + (N_models + 3) × k × N_executors × (executor pass)`.
- **Observer model pool** (initial, not locked): `anthropic/claude-sonnet-4-6`, `anthropic/claude-haiku-4-5`, `qwen/qwen3.6-27b`, `deepseek/deepseek-v4-flash`, `openai/gpt-oss-20b`, `xiaomi/mimo-v2-flash:free`.
- **Integrity:** every published number reproducible from this repo; publish everything including where Claude models lose; no silent metric or corpus changes; OpenRouter cited in everything published.

**How to use this plan:** each phase is self-contained and executable in a fresh context. Every task is framed as COPY from a cited source, not invent. Read the cited lines before writing code.

### 0.2 Anti-patterns (grep-able guards; Final Phase checks these)

1. **Never estimate cost.** `VAN/src/services/worker/OpenRouterAgent.ts:483` fabricates cost from hardcoded per-token rates — the exact failure MemBench exists to avoid. No pricing constants anywhere. `costUsd` comes only from reported usage, else stays `undefined` and the row says so.
2. **Never use the 70/30 token split.** `CM/src/services/worker/OpenAICompatibleProvider.ts:175-176` splits totals 70/30 as a fallback — benchmark rows use real `prompt_tokens`/`completion_tokens` or record `null`.
3. **Never drop a row.** Every fork-run writes a `results.jsonl` row even on timeout/crash (pattern: `SWB/run-batch.py:388-395`, bash trap `SWB/run-instance.sh:79-95`). Silent-return-on-timeout (`SWB2/run.py:277-280`) is the bug.
4. **Per-fork memory isolation is mandatory.** Shared `~/.claude-mem` across forks = cross-contamination (documented bug: `SWB2/README.md:103-106`). Every fork gets its own `CLAUDE_MEM_DATA_DIR` + port; the CLI executor gets an isolated `HOME` (pattern: `SWB/run-instance.sh:117,147`).
5. **No `--bare` on the claude CLI** — disables plugin/skill discovery (`SWB2/README.md:33-34`).
6. **Don't reimplement prompt/parser/injection** — vendor verbatim from `CM` with provenance headers. Don't "improve" the XML skeleton, truncation constants, or concept cleanup (`parser.ts:121-126` protects exact-string concept matching in `CM/src/services/context/ObservationCompiler.ts:20-71`).
7. **No raw INSERTs into claude-mem DBs** — schema has 30+ conditional migrations; column order varies per disk file. Go through `POST /api/import` only.
8. **Force `CLAUDE_MEM_RUNTIME=worker`** in every spawned worker/MCP env — otherwise `search` can silently reroute to a different backend (`CM/src/servers/mcp-server.ts:506-513`).
9. **Transcript parsing:** filter observer sessions out; `origin.kind=="human"` for prompts; `sessionId` not `session_id`; don't decode project dir names.
10. **Secrets:** never package `~/.claude-mem/.env`, `.auth-token`, `admin.token`, `secrets/`. Sanitize transcripts before freezing (Phase 3 list).
11. **Executor parity discipline:** the two executors are separate lanes. No scoreboard cell may mix `claude-cli` and `openrouter-agent` rows; cross-executor deltas live only in the cost table and diagnostics.

### 0.3 Known gaps (decisions embedded in phases)

- **No reliable repo-commit-at-session-end** exists in any data source (`observations.commit_sha` 0.6% populated; transcripts carry only `gitBranch`) → Phase 3 pins commits via `git log --until=<session-end>` on the recorded `cwd`, falling back to mining Bash tool output; unpinnable candidates are rejected.
- **No prior art for a single-command offline-testable harness** in the reference checkouts — the orchestration layer and offline tests are net-new, built from the `VAN/tests/gemini_agent.test.ts` mock pattern and `ORSB` governance conventions.
- Retry-with-backoff precedent: only `CM/src/services/worker/retry.ts` — port that one.

## Phase 6 — Orchestration: the full loop, cost governance, measurement

**Context needed:** Phases 1–5 outputs; §0.1 (`ORSB` governance); `SWB/run-batch.py:427-452` (run-dir + overwrite guard).

### Implement

1. **Stage 1 — observe (`cli.ts observe`)**: for each corpus item × observer model in the spec: run `observe-runner.ts` over `toolcalls.jsonl`, concurrent across models (cap ~4). Emit `runs/<run_id>/obs/<item>/<model>.json` = `{observations, parse_notes, obs_tokens_in, obs_tokens_out, obs_cost_usd}`. Synthesize `oracle` and `shuffled` sets (Phase 4.2).
2. **Stage 2–3 — fork + execute**: for each item × variant × executor × k: `prepareFork` → executor → teardown. Concurrency across forks bounded by spec; unique ports allocated from a pool.
3. **Stage 4 — measure (`src/measure.ts`)**: `success` = `check.sh` exit in the fork repo; `drift_flag` + `drift_note` = judge call (cheap model from spec, via the Phase 2 client) comparing `git diff` against `task.md` scope; row appended to `runs/<run_id>/results.jsonl` **immediately per run** (never batched).
4. **`cli.ts run`** ties it together with `ORSB` governance:
   - `--spec run-specs/<name>.toml --run-id <id>` required; run-id-scoped output tree + overwrite guard refusing to clobber partial results (`SWB/run-batch.py:440-452`)
   - `--dry-run`: validates spec + corpus, prints the full planned call matrix (`items × models` observe calls; `items × (models+3) × executors × k` executor runs) and, once any measured rates exist in `runs/`, a cost estimate — no network
   - Live runs **require `--approve-cost-usd <ceiling>`**: refuse to start when the estimate exceeds the ceiling; between items, stop when cumulative real `usage.cost` crosses it; on stop, the partial run remains resumable (completed rows detected via `results.jsonl`, pattern `SWB2/run.py:90-106`)
   - `--mock` swaps provider + executors for mocks so the entire loop dry-runs offline
5. **Offline e2e** — `tests/e2e-offline.test.ts`: fixture mini-corpus item (tiny repo in `tests/fixtures/`), mock provider (canned XML), both mock executors — assert `results.jsonl` has `(models+3) × executors × k` rows, all `ResultRow` fields present, injected timeout still yields a row with `error` set, resume skips completed rows.

## Design decisions

1. **Vendoring** `prompts.ts`/`parser.ts`/`code.json` from `CM @ 132b46343` with provenance headers, instead of depending on the claude-mem package — keeps the public repo self-contained and reproducible. Alternative rejected: git submodule (drags a 600MB repo into every clone).
2. **Two first-class executors in v0.1.** `claude-cli` benchmarks the production consumer; `openrouter-agent` opens the executor-side model matrix and produces real OpenRouter-routed pricing. They share the `Executor` interface and the fork/measurement pipeline, so the marginal build cost is one adapter each. Scoreboards never mix lanes.
3. **Injection by prompt-prepend** (fetch `/api/context/inject`, prepend to the task prompt) rather than a full claude-mem plugin install per fork `HOME` — identical injected content with far less machinery; session hooks are not under test. mem-search stays live in both lanes (MCP config for the CLI; same-named HTTP tools for the SDK executor).
4. **mem-search tools in the SDK executor call worker HTTP routes directly** with the same tool names as the MCP surface — the production MCP server is a thin proxy over those exact routes, so semantics match while removing a per-fork subprocess.
5. **Dependency policy**: zero runtime deps except the exact-pinned `@openrouter/agent` (+ `zod` peer), isolated behind the `Executor` interface so the rest of the harness builds and tests without it.
